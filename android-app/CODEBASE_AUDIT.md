# MobileCloud Android app and edge-node audit

**Audit date:** 2026-11-24 · **Source baseline:** `2393ec5` · **Release decision:** hold public APK distribution. After the release blockers are closed, position this build as a console client unless the on-device node passes separate runtime acceptance.

## Remediation status in the working tree

- Android now requires a confirmed HTTPS origin and uses same-origin WSS. QR setup only saves the new origin after claim and authenticated refresh, and reconnects refresh the account snapshot. Revocation is enforced by the shared API and gateway.
- The APK is intentionally console-only. The unsupported boot supervisor and node jobs were removed, and widgets no longer imply node health or verified reserves. Debug APK assembly and lint passed with JDK 17. The unsigned release APK targets API 35, packages ARM64 native code, is not debuggable, and passed 16 KiB ZIP alignment verification. Release signing has one verify-before-publish workflow.
- Do not distribute before assessing historical signing credential exposure, configuring the trusted signer fingerprint, and verifying a signed APK on arm64 hardware. Physical-device pairing, revocation, lifecycle, and accessibility acceptance are still open. The session remains in memory; process-death recovery and hardware-bound pairing are not implemented. The evidence below describes the original audit baseline.

## Scope and evidence

Reviewed the reachable Compose console, QR scanning/sign-in, discovery and networking, session lifecycle, realtime sync, services and workers, widgets, local security, dormant node screens, JNI/PTY, manifest, Gradle and signing/CI. Compared with shared API and gateway behavior and the [README](../README.md), [realtime design](../docs/REALTIME-SYNC.md) and [security model](../docs/SECURITY-MODEL.md). Shared Rust engine, ingress, and financial-service boundaries are summarized in the [web and shared platform audit](../apps/web-dashboard/CODEBASE_AUDIT.md). No signed release was produced, no device or emulator was exercised, and no live endpoints, custody claims, or historical secrets were verified.

| Check | Result |
|---|---|

## P1 — Release blockers

| ID | Finding and evidence | Required fix / closure gate |
|---|---|---|
| A-P1.01 | **Checked-out Kotlin has a compile blocker.** `signSorobanDigest` uses a bare return within an expression-bodied function. [Signer](app/src/main/kotlin/com/mobilecloud/security/HardwareAttestation.kt#L88) (88–98); [Kotlin plugin](build.gradle.kts#L1). | Use a block body or keep null handling within the expression. Verify current debug compile and release build in CI. |
| A-P1.02 | **Signing passwords are committed.** The tracked Windows signing script contains literal store/key passwords; the Gradle release configuration expects protected environment inputs. A local keystore was present outside the repo, but the review did not establish private-key exposure. [Signing script](../scripts/sign-release.bat#L6) (6–17); [Gradle](app/build.gradle.kts#L47) (47–58). | Rotate exposed passwords, assess where the keystore was copied, and use protected CI secret inputs. Assess signing-key replacement through the actual distribution channel if exposure is suspected. Removing literals from HEAD is not rotation. |
| A-P1.03 | **Release permits credential traffic over cleartext.** The network policy allows HTTP generally, not just loopback, and the raw realtime implementation also permits plaintext. Server cookies are not marked `Secure`. [Network policy](app/src/main/res/xml/network_security_config.xml#L2); [HTTP client](app/src/main/kotlin/com/mobilecloud/console/CloudClient.kt#L42); [realtime](app/src/main/kotlin/com/mobilecloud/console/RealtimeClient.kt#L391); [cookie](../apps/web-dashboard/lib/server/api.ts#L35). | Require HTTPS/WSS in release, with debug-only local exceptions. Verify release cannot send sign-in, pairing or session data to a plaintext endpoint. |
| A-P1.04 | **Discovery can change the destination of password login.** Discovery treats reachability or a product-name response as identity and can replace a manually entered server during fallback. [Discovery](app/src/main/kotlin/com/mobilecloud/console/ConsoleDiscovery.kt#L123) (123–142, 188–220); [sign-in and fallback](app/src/main/kotlin/com/mobilecloud/console/ConsoleStore.kt#L281) (281–312, 345–352). | Confirm and pin the chosen origin to that account connection; do not redirect, fail over or retry credential-bearing requests on another origin. |
| A-P1.05 | **Realtime credential selection bypasses cookie scope and peer verification.** The raw TLS socket does not enable endpoint hostname checking. The first session in a process-wide jar is selected without target scoping; switching endpoints does not clear it. [Realtime client](app/src/main/kotlin/com/mobilecloud/console/RealtimeClient.kt#L391) (391–458); [HTTP jar](app/src/main/kotlin/com/mobilecloud/console/CloudClient.kt#L25); [endpoint change](app/src/main/kotlin/com/mobilecloud/console/ConsoleStore.kt#L176). | Adopt a maintained WebSocket client with standard hostname verification and handshake integrity; partition credentials by approved origin/account. |
| A-P1.06 | **Revoked devices can keep an HTTP session and an existing socket.** Claim mints two credentials; revocation deletes the device bearer but doesn't revoke the session Android uses. Active sockets are not revalidated. [Claim](../apps/web-dashboard/lib/server/api.ts#L396); [revoke](../apps/web-dashboard/lib/server/pairing.ts#L434); [gateway liveness](../apps/web-dashboard/server/realtime.mjs#L550). | Bind sessions to devices and revoke matching credentials/sockets together. Verify revoke, logout and expiry stop HTTP and live delivery. |
| A-P1.07 | **Boot starts a prohibited foreground service on Android 15.** The app targets 35 and starts the `dataSync` network service from `BOOT_COMPLETED` without handling the Android 15 runtime budget either. [Gradle](app/build.gradle.kts#L21); [manifest](app/src/main/AndroidManifest.xml#L39); [boot receiver](app/src/main/kotlin/com/mobilecloud/service/BootCompletedReceiver.kt#L10); [network service](app/src/main/kotlin/com/mobilecloud/service/NetworkBunderService.kt#L42). | Observe the default network while needed, move bounded background work to a supported mechanism, and test boot and any retained service timeout with target 35. |
| A-P1.08 | **Release CI signs twice or fails to find the artifact.** Gradle inputs enable release signing, but tag CI unconditionally expects the unsigned APK for external signing. The shell release path may also try to reprocess an already signed APK. [Gradle](app/build.gradle.kts#L47); [CI](../.github/workflows/ci.yml#L93) (93–131); [release script](../scripts/build-and-sign-apk.sh#L47). | Use one signing owner, use the wrapper, validate required inputs, and verify the exact artifact and certificate before publication. |

## P2 — Pairing, sync, and core-user flows

| ID | Finding and evidence | Required fix |
|---|---|---|
| A-P2.01 | **Localhost pairing QR is unusable from a separate phone.** The ticket embeds the browser-facing origin; loopback points to the phone itself, and pairing doesn't use discovery. [Server origin](../apps/web-dashboard/lib/server/api.ts#L178) (178–190, 840–855); [scanner](app/src/main/kotlin/com/mobilecloud/ui/console/QrPairing.kt#L113). | Configure a phone-reachable HTTPS origin and warn at ticket creation if it is loopback. Document LAN, ingress and USB use separately. |
| A-P2.02 | **Pairing does not survive process death.** Android ignores the returned device credential and depends on an in-memory cookie jar that console recreation can replace. This is missing persistence, not a plaintext session preference. [Claim payload](../apps/web-dashboard/lib/server/api.ts#L412); [scanner](app/src/main/kotlin/com/mobilecloud/ui/console/QrPairing.kt#L125); [console root](app/src/main/kotlin/com/mobilecloud/ui/console/ConsoleRoot.kt#L50). | After revocation is effective, persist an origin-scoped, revocable credential with Keystore-backed encryption and a renewal flow. |
| A-P2.03 | **A scan can replace the saved server before approval and can report false success.** QR parsing is loose about version and destination; no comparison code is shown, the endpoint changes before claim, and a failed authenticated refresh does not prevent the success phase. [Pairing UI](app/src/main/kotlin/com/mobilecloud/ui/console/QrPairing.kt#L65) (65–87, 101–139, 169–195); [store](app/src/main/kotlin/com/mobilecloud/console/ConsoleStore.kt#L176) (176–182, 213–255). | Validate the ticket schema, origin and device-held proof. Keep an isolated pairing connection, save only after identity verification, and preserve the working account on cancel/failure. |
| A-P2.04 | **Reverse-proxied REST can work while Android realtime fails.** The client uses the discovery-advertised gateway listener port with the HTTPS host rather than the public WSS origin. [Realtime](app/src/main/kotlin/com/mobilecloud/console/RealtimeClient.kt#L391); [server health](../apps/web-dashboard/lib/server/api.ts#L464). | Publish and validate a canonical WSS URL/path; handle production proxy and explicit local configuration separately. |
| A-P2.05 | **Cursor recovery can skip changes and see spurious gaps.** Global event IDs are filtered per account, but Android assumes adjacency, shares live/replay state, and can advance progress before application completes. Ephemeral updates should not move durable progress. [Realtime](app/src/main/kotlin/com/mobilecloud/console/RealtimeClient.kt#L254) (254–282, 310–378, 540–544); [gateway](../apps/web-dashboard/server/realtime.mjs#L316) (316–343, 528–578). | Introduce account-specific predecessor semantics, snapshot watermarks and serialized last-applied checkpoints scoped by account and origin. |
| A-P2.06 | **Old reconnect work can disrupt a new session.** Cancellation doesn't join old work; connection generations share socket and cursor state, and ack/heartbeat/close writes are not serialized. [Realtime](app/src/main/kotlin/com/mobilecloud/console/RealtimeClient.kt#L106) (106–175, 192–240, 344–378, 497–537). | Own socket and jobs per generation, serialize writes, and clear or join prior state before replacing it. |
| A-P2.07 | **Refresh can strand stale data or mix state across endpoints.** A transient refresh error switches to `ERROR`, disabling safety polling. API calls in one refresh use mutable endpoints; late results can follow logout. Automatic retry of writes after I/O failure can duplicate a mutation. [Store](app/src/main/kotlin/com/mobilecloud/console/ConsoleStore.kt#L213) (213–255, 281–313, 329–396); [UI poll](app/src/main/kotlin/com/mobilecloud/ui/console/ConsoleShell.kt#L144); [HTTP client](app/src/main/kotlin/com/mobilecloud/console/CloudClient.kt#L42). | Scope operations to an immutable session, clear data on definitive auth loss, retain a retryable stale state for network errors, and retry writes only with server-side idempotency. |
| A-P2.08 | **The shipped Android configuration does not package an edge daemon.** The supervisor has a spawn loop and checks for a binary; tracked build steps package the PoR library instead. The proposed writable-storage execution path is not a reliable supported Android runtime. [Supervisor](app/src/main/kotlin/com/mobilecloud/service/CloudSupervisorService.kt#L135) (135–155, 196–242); [release script](../scripts/build-and-sign-apk.sh#L31); [CI](../.github/workflows/ci.yml#L85). | Label this build console-only. To ship node mode, package a supported runtime and prove presence, startup, authenticated readiness and teardown on hardware. |
| A-P2.09 | **App Lock has no reachable enrollment control.** It defaults off; the legacy security screen reports state, and live console settings are server-side. [Lock manager](app/src/main/kotlin/com/mobilecloud/security/AppLockManager.kt#L33); [routing](app/src/main/kotlin/com/mobilecloud/ui/MainActivity.kt#L53); [legacy screen](app/src/main/kotlin/com/mobilecloud/ui/screens/SecurityScreen.kt#L160). | Expose an authenticated, device-local control if desired; distinguish UI privacy from key, daemon or API authorization. |

| ID | Finding and evidence | Required fix |
|---|---|---|

| A-P3.02 | **Pairing commit and publication are not a single operation.** Claim can consume a ticket before outbox publication and session creation finish. [Claim](../apps/web-dashboard/lib/server/api.ts#L396); [outbox](../apps/web-dashboard/lib/server/events.ts#L72). | Persist claim, credential, session and event together. | A-P3.03 | **Daemon HMAC is stored in plaintext preferences; diagnostics and reveal surfaces are not consistently protected.** No direct password log was observed. | A-P3.04 | **PoR widget can show unverified or stale evidence as healthy.** It trusts a ratio response and treats fetch time as freshness without verifying evidence, signatures or quorum. ## P4 — Lifecycle, power, and telemetry

| ID | Finding and evidence | Required fix |
|---|---|---|
| A-P4.01 | **Node work starts without opt-in or a user-facing stop action.** Console-only users start foreground services and workers; the supervisor can renew wake locks even without a daemon. [Activity](app/src/main/kotlin/com/mobilecloud/ui/MainActivity.kt#L43) (43–48, 80–109); [application](app/src/main/kotlin/com/mobilecloud/MobileCloudApp.kt#L26); [supervisor](app/src/main/kotlin/com/mobilecloud/service/CloudSupervisorService.kt#L48). | Make node runtime opt-in, add a stop action, and acquire wake locks only while required. |
| A-P4.02 | **Spawn and service teardown can race.** Blocking spawn, log reads and wait are not coordinated with cancellation; a process can appear after teardown checks its handle. Spawn is reported as running before readiness. [Supervisor](app/src/main/kotlin/com/mobilecloud/service/CloudSupervisorService.kt#L157) (157–192, 250–261, 287–295, 317–327). | Make process ownership explicit, close streams and join teardown, and report running only after authenticated health. |
| A-P4.03 | **Dual-WAN tracking does not control console traffic.** Distinct network references exist, but HTTP and WebSocket use default system routing. Non-default network changes can still trigger reconnect. [Network service](app/src/main/kotlin/com/mobilecloud/service/NetworkBunderService.kt#L61); [HTTP](app/src/main/kotlin/com/mobilecloud/console/CloudClient.kt#L47); [realtime](app/src/main/kotlin/com/mobilecloud/console/RealtimeClient.kt#L410); [store](app/src/main/kotlin/com/mobilecloud/console/ConsoleStore.kt#L135). | Observe the default network or bind both transports explicitly and measure failover. |
| A-P4.04 | **Workers do not catch up console state in the background.** Scheduled work is widget telemetry and a loopback PoR read. Failed reads wait until the next interval. [Schedule](app/src/main/kotlin/com/mobilecloud/work/WorkerScheduler.kt#L27); [telemetry](app/src/main/kotlin/com/mobilecloud/work/TelemetryWorker.kt#L24); [PoR worker](app/src/main/kotlin/com/mobilecloud/work/PorAttestationWorker.kt#L22). | Document the scope, or add constrained authenticated catch-up with practical retry and freshness semantics. |
| A-P4.05 | **Battery bypass and thermal protection overstate what is enforced.** Battery detection has guessed defaults and does not prove isolation; the unsupported-current sentinel is not handled before absolute value. [Battery](app/src/main/kotlin/com/mobilecloud/service/BatteryBypassDetector.kt#L40); [supervisor](app/src/main/kotlin/com/mobilecloud/service/CloudSupervisorService.kt#L96); [node mode](app/src/main/kotlin/com/mobilecloud/core/NodeMode.kt#L91). | Preserve unknown readings, label estimates as estimates, and gate actual workload with verified thresholds and hardware halt/resume checks. |
| A-P4.06 | **Discovery deadline and network range are approximate.** Blocking probes and body reads can exceed cancellation; LAN probing assumes a `/24`. [Discovery](app/src/main/kotlin/com/mobilecloud/console/ConsoleDiscovery.kt#L67) (67–91, 123–177, 200–220). | Use bounded cancellable probes, stop after the first suitable candidate and require explicit intent for LAN discovery. |

## P6 — Native terminal and interaction reliability

The local PTY findings apply if the dormant local terminal is exposed; no reachable activity route or intent to that PTY was established by this review.

| ID | Finding and evidence | Required fix |
|---|---|---|
| A-P6.01 | **PTY reader and child lifetime are not owned deterministically.** Its executor isn't shut down, and native code does not track the specific child through reaping. [Controller](app/src/main/kotlin/com/mobilecloud/terminal/NativePtyController.kt#L37) (37–48, 71–91, 150–157, 221–243); [JNI](app/src/main/cpp/jni_bridge.cpp#L61) (61–89, 125–131). | Keep a per-session native handle, close file descriptors, terminate and reap the owned child, and shut down its executor. |
| A-P6.02 | **PTY input can truncate and JNI does not validate argument lengths.** Partial/native writes are not retried, and caller lengths are not validated against Java array bounds. No remote overflow was verified. [Controller](app/src/main/kotlin/com/mobilecloud/terminal/NativePtyController.kt#L202); [JNI](app/src/main/cpp/jni_bridge.cpp#L92). | Validate bounds and JNI results, serialize writes and drain them fully or return a visible error. |
| A-P6.03 | **Local shell is not a separate sandbox.** The native shell inherits the app UID, environment and open resources; `HOME` and `PATH` do not establish isolation. [App dirs](app/src/main/kotlin/com/mobilecloud/AppDirs.kt#L11); [controller](app/src/main/kotlin/com/mobilecloud/terminal/NativePtyController.kt#L71); [JNI](app/src/main/cpp/jni_bridge.cpp#L61). | Define the local trust boundary, minimize inheritance, and keep this separate from remote commands. |
| A-P6.04 | **Terminal parsing and rendering are fragile under partial data and resize.** UTF-8 handling improved, but ANSI parsing is not streaming, cursor bounds are incomplete, and drawing continues while idle. [Canvas/parser](app/src/main/kotlin/com/mobilecloud/terminal/TerminalSurfaceView.kt#L35) (35–60, 64–152, 248–315). | Use a bounded streaming parser and layout-derived grid; test incremental output, cursor movement and resize. |
| A-P6.05 | **Forms lose drafts and some handlers can read cleared values.** Asynchronous action callbacks read mutable fields that are reset immediately after dispatch. [Action helper](app/src/main/kotlin/com/mobilecloud/ui/console/ConsoleActions.kt#L19); [project form](app/src/main/kotlin/com/mobilecloud/ui/console/pages/ProjectPages.kt#L237); [infra](app/src/main/kotlin/com/mobilecloud/ui/console/pages/InfraPages.kt#L127); [security](app/src/main/kotlin/com/mobilecloud/ui/console/pages/SecurityPages.kt#L373). | Snapshot the payload, show per-action pending/error state, and clear drafts on success only. |
| A-P6.06 | **Remounting legacy screens would introduce blocking UI work.** Some UI effects do sysfs reads, key operations or blocking HTTP on their current context. [Dashboard](app/src/main/kotlin/com/mobilecloud/ui/screens/DashboardScreen.kt#L75); [hardware](app/src/main/kotlin/com/mobilecloud/ui/screens/HardwareSettingsScreen.kt#L65); [PoR view](app/src/main/kotlin/com/mobilecloud/ui/screens/ProofOfReserveScreen.kt#L52); [probe](app/src/main/kotlin/com/mobilecloud/work/CoreEngineProbe.kt#L22). | Move it to lifecycle-aware I/O with explicit loading and failure state before exposing these screens. |

## Verified positives and fix order

- Manifest disables backups and keeps services and widgets non-exported. The intended launcher is exported; the boot receiver checks its received actions. [Manifest](app/src/main/AndroidManifest.xml#L27); [receiver](app/src/main/kotlin/com/mobilecloud/service/BootCompletedReceiver.kt#L10).
- QR claim requires a high-entropy secret plus browser approval and transactionally consumes one claim with device creation. The scanner handles camera permission and cancel. See [pairing](../apps/web-dashboard/lib/server/pairing.ts#L337) and [scanner](app/src/main/kotlin/com/mobilecloud/ui/console/QrPairing.kt#L169). Replay filters by account and reconnect uses bounded delays/jitter; checkpoint and credential ownership remain open.
- Prior fixes improved bounded wake-lock acquisition, distinct Wi-Fi/cellular references, PTY idle wait, split UTF-8, biometric rotation and missing-daemon reporting. They do not prove node startup, traffic failover or terminal isolation. [Supervisor](app/src/main/kotlin/com/mobilecloud/service/CloudSupervisorService.kt#L144); [PTY controller](app/src/main/kotlin/com/mobilecloud/terminal/NativePtyController.kt#L150).
- **Release sequence:** rotate exposed passwords and assess keystore custody → compile and verify one release signing path → repair HTTPS/WSS, discovery and revocation → fix Android 15 service startup and pair/resync reliability → verify on two real clients → ship node/financial controls only under separate acceptance.
